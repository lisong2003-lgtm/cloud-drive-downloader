# 36 · Web UI 实时进度规范

## 必须做到
0. **普通终端下载自动开 Web UI**：`pan get` 默认启动/复用本地服务并打开 `/live`；`--no-web` 可关闭。
1. **Agent/无人值守不弹窗**：`--json`、`--events`、MCP、后台和 Web UI 投递任务不得嵌套打开浏览器。
2. **链接秒级门禁**：投递前先做纯本地登录/授权检查；需要登录时立即展示 `/login?drive=<网盘>`，不能等下载失败才提示。
3. **登录后直接回 Web UI**，不要把用户留在临时终端或临时页面。
4. **任务必须可见**：文件名、网盘、引擎、状态、进度、速度、剩余时间、下载位置。
5. **下载位置可复制**：任务中心和 `/live` 都要显示本地路径，并提供“复制路径”按钮。
6. **下载中不做聊天轮询**：状态页面自动刷新，Agent 不再额外消耗对话。
7. **完成后在页面显示本地文件路径**，并允许重试/暂停/删除。
8. **端口失败不影响下载**：端口被占用或系统禁止监听时，终端只给警告，下载继续；不能因 Web UI 启动失败中断任务。

## 页面分工
- `/`：任务中心，一体化展示所有任务、下载位置和复制路径。
- `/live`：自动弹出的实时速度、进度曲线、状态明细、下载位置和复制路径。
- `/login`：统一登录/授权入口。
- `/test`：下载前检查。

## 命令行为
- `pan get <链接>`：交互终端默认自动启动/复用 Web UI 并打开 `/live`，同时写入实时状态。
- `pan get <链接> --no-web`：不启动、不打开 Web UI；显式 `--live` 仍可写状态供已有服务查看。
- `pan get --json` / `--events` / MCP / 后台任务：不弹窗；需要状态时显式 `--live`。
- 默认端口取 `deployment.web_port`，未配置时 `17890`；连续 6 个端口都无法监听则静默降级。

## 反模式
- 只在聊天里发一句“下载中”。
- 用临时脚本绕开 Web UI。
- 让用户贴 Cookie / 密码到聊天。
- 只报告 rc=0 却没有实际文件。

## 外部引擎接入

BaiduPCS-Go 等外部进程不能直接回调本 Skill 时，用日志桥接入同一个 Web UI：

```bash
python3 <pan-root>/scripts/pan.py live attach \
  --log <BaiduPCS-Go 下载日志> \
  --target <实际下载目录> \
  --total-bytes <分享总字节> \
  --files-total <分享文件数> \
  --pid <BaiduPCS-Go PID> \
  --state-dir <Web UI reports-dir> \
  --open
```

- `/live` 同时显示：分享总进度、当前批次百分比、活动分片数、速度、ETA、当前文件和下载位置，页面每 10 秒自动刷新（可在浏览器里手动刷新看最新值）；
- 外部日志中的 0 B/s 会如实标记为“限速或等待分片”，不会伪装成高速；
- 进程退出后自动停止监控；仍有 `.BaiduPCS-Go-downloading` 标记时标记为未完成，不误报成功。

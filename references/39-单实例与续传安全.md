# 39 · 单实例、续传安全与限速诚实报告

> v0.16.0 新增。把 2026-10-15 两次实测的教训固化成可执行规则：
> 一次成功（扫码 → 转存 → 从自己网盘断点续传），一次失败（多进程抢同一批文件）。

## 0. 优化方向和目标

1. **单入口、少操作**：用户只给链接和提取码；登录只在需要时走 `pan login <网盘> --qr`，不粘贴 Cookie。
2. **单实例互斥**：同一 `(drive, source, target)` 只跑一个进程，防止六进程抢文件、互相覆盖断点。
3. **续传安全**：下载失败或中断后直接续传；禁止 `--ow` 导致已下分片从头重下。
4. **后台可靠常驻**：后台任务用双 fork + `setsid`，替代会在调用方退出后被回收的 `nohup ... &`。
5. **速度与错误如实报告**：先采样吞吐、计算 ETA，再区分限速、登录、验证码、风控、直链缺失和磁盘不足。
6. **扫码稳定**：每次登录生成唯一二维码文件，避免路径缓存导致“二维码错误”；登录成功后不反复重登。
7. **验收以结果为准**：文件数/大小核对通过才算完成；平台限制、沙箱限制和免费账号限速必须明确列出。

## 1. 成功流程（已验证，照抄即可）

```
分享链接 + 提取码
  → ① 识别网盘 / 提取码 / 是否文件夹
  → ② pan route <链接> --json --brief        # 只做识别 + 登录门禁，不联网刷屏
  → ③ 需要登录时：pan login baidu --qr       # 唯一登录入口，每次生成唯一二维码文件
  → ④ 分享内容先转存到自己网盘（BaiduPCS-Go transfer）
  → ⑤ 从"自己网盘"断点续传下载（不是从分享链接直下）
  → ⑥ 任务进 Web UI 任务中心 + /live，不在聊天里轮询
  → ⑦ 完成后核对文件数/大小，输出本地路径
```

要点：**扫码成功后不要反复重登**；转存一次即可；下载阶段只跑**一个**进程。

## 2. 硬规则：同一来源只允许一个下载进程

失败现场（2026-10-15）：为测速先后起了 6 个 BaiduPCS-Go 进程，全部写同一批文件，
互相抢带宽、互相覆盖断点，表现为"跑了几十分钟没有进展"。

- 计划步骤带 `lock`，百度官方网页会话路径带 `web_lock`；执行前必须抢锁，抢不到直接退出码 `9`，并打印持有者 pid/开始时间。
- 锁粒度：`(drive, source, target)` 三元组，散列后放 `$PAN_LOCK_DIR`（默认 `STATE_DIR/locks`，不可写时退到系统临时目录）。
- 陈旧锁（pid 已死）自动接管；也可手动 `pan guard clean`。
- 查看当前锁：`pan guard status`（或 `pan guard locks --json`）。

## 3. 硬规则：续传场景禁止 `--ow`

`--ow` 会让已经下好的分片从头重下。计划构建阶段会**自动剥离** `--ow`（含写在
`config.json` 的 `drives.*.engine_command` 里的），并补 `--retry 5`。

## 4. 硬规则：后台常驻用双 fork，不用 nohup

实测 `nohup ... & disown` 起的进程会随调用方退出被回收，任务静默死掉。
统一入口：

```bash
pan guard daemon --cmd 'pan get "<链接>" --to <目录>' --log <日志>
```

内部是 `os.fork()` → `setsid()` → 再 `os.fork()`，与调用方完全脱钩。

## 5. 硬规则：限速要如实报告，不混入"登录失败"

- `pan guard speed --target <目录> --seconds 20`：采样真实吞吐。
- 低于 **200 KB/s** 判定为"网盘侧限速/免费账号"特征，输出明确提示；不破解限速。
- 实测基线：百度免费账号 30–120 KB/s；本机 OVH/Cloudflare 单连接 1.9–5.2 MB/s；
  出口 IP 为用户真实公网 IP → 瓶颈在网盘侧，与本机/沙箱无关。
- `pan guard eta --total <字节> --bps <每秒字节>`：把速度换算成可读剩余时间。

## 6. 错误分类（不要把不同问题混为一谈）

`pan guard error --text '<原始错误>'` → 统一错误码 + 处置建议：

| 错误码 | 触发特征 | 处置 |
|---|---|---|
| `login_required` | 未登录 / BDUSS 失效 | `pan login <网盘> --qr`（唯一入口） |
| `dlink_missing` | 未返回下载直链 | 先转存到自己网盘再走 baidupcs |
| `captcha` | 验证码 | 人工在官方网页完成，工具不破解 |
| `risk_control` | 风控 | 等一段时间再试，不要高频重试 |
| `http_403` | 直链 403 | 登录态过期/无权限，重登后重跑（断点续传） |
| `not_found` | 文件/分享不存在 | 核对链接与提取码 |
| `disk_full` | 空间不足 | 清理磁盘；断点保留 |
| `throttle` | 限速 | 如实报告；可选会员提速 |

## 7. 验收清单

- [ ] 同来源第二次启动会被拒（退出码 9），提示持有者 pid；BaiduPCS 与官方网页路径都覆盖。
- [ ] 计划里百度下载步骤带 `lock`、带 `--retry`、**不带** `--ow`。
- [ ] `config.json` 里写死的 `--ow` 也被剥离。
- [ ] 守护化进程在调用方退出后仍然存活。
- [ ] 测速低于阈值时输出"限速"提示，而不是"登录失败"。
